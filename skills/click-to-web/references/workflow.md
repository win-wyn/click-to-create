# Click-to-Create — เลือกผลลัพธ์และเก็บเนื้อหาร่วมกัน

## เลือกรูปแบบก่อนเริ่ม

- เมื่อผู้ใช้เรียกชุด Click-to-Create หรือสกิลใดในชุดนี้โดยยังไม่เลือกรูปแบบ ให้ถามครั้งเดียวว่า **ต้องการ PDF / Web / Video อะไรบ้าง? เลือกได้มากกว่าหนึ่ง** รอคำตอบก่อนสร้างผลลัพธ์ การทำงานหลักที่อนุมัติแล้วและไม่ขึ้นกับคำตอบทำต่อได้
- ถ้าระบุรูปแบบชัดแล้ว เช่น PDF อย่างเดียว, เว็บอย่างเดียว, วิดีโออย่างเดียว หรือเรียก $click-to-pdf ให้ถือว่าเลือกรูปแบบนั้นแล้ว ไม่ถามซ้ำและไม่เพิ่มรูปแบบอื่นเอง หากเรียกหลายสกิลให้รวมเป็นคำขอเดียว
- เมื่อตัวเลือกยังไม่พร้อม ให้แจ้งก่อนเริ่มและทำเฉพาะส่วนที่มีเครื่องมือรองรับ อย่าเปลี่ยนเป็นรูปแบบอื่นหรือสร้างเพิ่มแทนโดยไม่ตกลง
- PDF, Web และ Video เป็นผลลัพธ์อิสระ PDF ไม่บังคับส่งเว็บหรือ HTML และ Video ไม่ต้องรอ PDF/Web เสร็จก่อน ไม่มีคำถามเสนอวิดีโอซ้ำท้ายงานเมื่อเลือกรูปแบบครบแล้ว
- หากเลือกหลายรูปแบบ ตรวจว่าสกิลเพื่อนที่เลือกมีจริงก่อนเรียก ไม่ติดตั้งเพิ่มเอง ถ้าไม่มีให้แจ้งส่วนที่ทำไม่ได้ ชุดนี้มีเพียง click-to-pdf, click-to-web, click-to-video ไม่มีคำสั่ง $click-to-create เป็นสกิลตัวที่สี่

## ขอบเขตและที่เก็บ

- ทำงานครั้งแรกพร้อมเก็บวิธีทำ ไม่เปลี่ยนงานที่ API/เครื่องมือเฉพาะทำได้ให้เป็นงานคลิกเพื่อสร้างคู่มือ ใช้ Browser/Computer ตามข้อกำหนดของเครื่องมือเมื่อจำเป็น
- พิจารณาเสนอชุดนี้กับงาน UI ที่ทำซ้ำได้ ข้ามงานค้นข้อมูลทั่วไป การแก้ปัญหาเฉพาะครั้ง และคู่มือเดิมที่ยังใช้ได้ ผู้ใช้ไม่ต้องการผลลัพธ์เพิ่มให้ทำเฉพาะงานหลัก
- ตรวจคู่มือเดิมเฉพาะบริบทและคลังที่อนุมัติ ไม่ค้นทั้งเครื่องหรือไล่อ่านทุกแชต ถ้ามีของเดิมตรงงานให้ส่งลิงก์เดิมหรือปรับเฉพาะจุด
- ใช้ตำแหน่งไฟล์ที่ผู้ใช้ตกลงสำหรับงานนั้น หากยังไม่มีให้ถามและเก็บชั่วคราวในพื้นที่งานเดิม การอนุมัติที่เก็บสกิลไม่ใช่สิทธิ์สร้างโฟลเดอร์หรือแชร์ Cloud ทุกงาน
- ทุกผลลัพธ์ใช้ชุดขั้นตอน ภาพที่ปิดบังข้อมูลแล้ว หมายเลข และวันที่ตรวจเดียวกัน ถ้าเลือกหลายรูปแบบ เก็บเนื้อหาอ้างอิงร่วมในพื้นที่งานเดิมตามสิทธิ์ ไม่บังคับเผยแพร่ไฟล์ต้นฉบับหรือสร้างผลงานอีกชนิดหนึ่ง
- อ่านกติกาการออกแบบที่ references/design.md ของสกิลที่กำลังใช้ เครื่องมือ PDF/วิดีโอเป็นตัวช่วยเมื่อมีจริง ห้ามติดตั้ง dependency บริการ หรือซื้อเครดิตเพิ่มเอง

## เก็บระหว่างทำ

1. สรุปสั้น ๆ ว่าจะทำงานหลักพร้อมเก็บคู่มือ ใช้เครื่องมือและสกิล Browser/Computer ที่มีอยู่ตามข้อกำหนดของเครื่องมือนั้น
2. บันทึกจุดเริ่มต้น เมนู ชื่อปุ่ม ค่าที่เลือก เงื่อนไขหรือสิทธิ์ที่จำเป็น และผลที่สังเกตได้จากงานจริง แยกค่าตัวอย่างจากค่าที่ผู้ใช้ต้องเลือกเอง
3. แคปภาพเฉพาะหน้าจอสำคัญที่ช่วยหาปุ่มหรือเข้าใจผล ระหว่างอยู่หน้านั้น ใช้ภาพเดียวอธิบายหลายขั้นตอนที่ต่อเนื่องกันได้ ไม่แคปทุกคลิก
4. ใช้ภาพหน้าจอจริงเป็นหลัก รักษาบริบทพอให้เทียบกับแอปได้ และเพิ่มหมายเลข/ลูกศรโดยไม่บังปุ่มหรือค่าที่ต้องอ่าน
5. หลีกเลี่ยงภาพที่แสดงรหัสผ่าน OTP token ข้อมูลบุคคลหรือข้อมูลธุรกิจที่ไม่จำเป็น ปิดบังข้อมูลเหล่านั้นในภาพที่จะฝังหรือส่งมอบ เลือกข้อมูลตัวอย่างปลอดภัยเมื่อทำได้ภายในสิทธิ์เดิม
6. ภาพ Gen ใช้เฉพาะภาพประกอบที่ช่วยอธิบายและคุ้มกับงาน ติดป้ายว่าเป็นภาพประกอบ ไม่อ้างว่าเป็นภาพ UI จริงหรือใช้ยืนยันชื่อปุ่ม/สถานะ หากไม่มีภาพจริง ให้ระบุส่วนที่ยังยืนยันไม่ได้

การทำคู่มือไม่เพิ่มสิทธิ์ทำธุรกรรม ส่งข้อมูล เปลี่ยนระบบ หรือทดลองกับข้อมูลจริง หากต้องกลับเข้าแอป ทำรายการซ้ำ หรือทำขั้นตอนที่มีผลต่อข้อมูลเพื่อเก็บภาพเพิ่ม ให้แจ้งเหตุผลและขออนุญาตเฉพาะส่วนที่อยู่นอกงานเดิมก่อน ใช้หลักฐานที่เก็บไว้ทำส่วนที่เหลือได้ต่อ

## เขียนให้ทำตามได้

ใช้ภาษาไทย กระชับ และคงชื่อเมนู/ปุ่มตามหน้าจอจริง คู่มือควรมี:

- ชื่องาน เว็บไซต์/แอป และวันที่ตรวจขั้นตอน ระบุรุ่นเมื่อทราบ ไม่เดารุ่น
- จุดเริ่มต้นและสิ่งที่ต้องเตรียมเฉพาะที่จำเป็น ไม่ใส่ข้อมูลเข้าใช้งานลับ
- ขั้นตอนตามลำดับในรูป `หน้า → ปุ่ม → ค่า/สิ่งที่เลือก → ผลที่ควรเห็น` พร้อมภาพอ้างอิงและหมายเลขตรงกัน
- เกณฑ์รู้ว่าทำสำเร็จ และข้อควรระวังเฉพาะงาน เช่น บันทึกร่างต่างจากส่งจริงอย่างไร เมื่อยืนยันได้จากระบบ
- วิธีแก้ปัญหาสั้น ๆ เฉพาะที่พบหรือยืนยันได้ ไม่แต่งเมนู กรณีผิดพลาด หรือวิธีคืนค่าขึ้นเอง

ใช้ `<ค่าที่ต้องเลือกเอง>` แทนข้อมูลเฉพาะครั้ง และบอกวิธีเลือกเมื่อจำเป็น ทำให้ผู้ใช้เปลี่ยนเดือน ชื่อไฟล์ หรือรายการได้ ไม่ผูกคู่มือกับข้อมูลครั้งเดียว หากงานหยุดหรือไม่สำเร็จ ให้บอกขอบเขตที่ยืนยันแล้วและจุดที่ยังค้าง ไม่เรียกเป็นคู่มือที่ผ่านครบกระบวนการ


## ตรวจและบันทึกเข้าคลัง

- ตรวจชื่อปุ่ม ลำดับ ค่า และผลกับหลักฐานจริง ไม่ทำรายการที่มีผลต่อข้อมูลซ้ำเพื่อเก็บภาพหรือทดสอบคู่มือ ไม่อ้างว่าผู้ใช้ใหม่ทำตามสำเร็จถ้ายังไม่ทดลอง
- หลังตรวจเฉพาะรูปแบบที่เลือก อ่าน references/library.md และบันทึกไฟล์ส่งมอบเข้าคลังที่ตั้งค่าไว้ หากยังไม่พร้อมให้รายงานส่วนค้างตามจริง
- ส่งลิงก์รายการคลังและผลลัพธ์ที่เลือก ระบุว่าทำจริง/ผ่าน/ยังไม่ทำอะไรบ้าง ไม่รับรองจำนวนโทเคนหรือเวลาที่จะประหยัดได้
- สกิลเป็นคำสั่งที่ AI ต้องมองเห็นและโหลด ไม่ใช่ระบบเฝ้าจอหรือรวบรวมทุกแชตอัตโนมัติ ไม่แก้สกิลอื่น Instructions หรือสร้าง automation นอกงานที่อนุมัติ
