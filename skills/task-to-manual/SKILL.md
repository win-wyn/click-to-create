# Task to Manual

ทำงานครั้งแรกพร้อมเก็บวิธีทำ เพื่อให้ผู้ใช้ทำงานเดิมเองครั้งถัดไปได้ ใช้คู่มือสั้นตามความซับซ้อนของงาน ไม่รับรองจำนวนโทเคนหรือเวลาที่จะประหยัดได้

## เลือกใช้ให้ตรงงาน

- พิจารณาใช้เองเมื่องานที่ได้รับมอบหมายต้องทำผ่าน Browser/Computer และเป็นกิจกรรมที่ทำซ้ำได้ เช่น ส่งออกรายงาน เปลี่ยนค่าตั้ง หรือกรอกแบบฟอร์มตามขั้นตอนเดิม ผู้ใช้ไม่ต้องสั่งทำคู่มือซ้ำทุกครั้ง
- ทำงานหลักให้สำเร็จควบคู่กับเก็บขั้นตอน ไม่เปลี่ยนงานที่ทำผ่าน API/เครื่องมือเฉพาะได้อยู่แล้วให้กลายเป็นงานคลิกเพียงเพื่อสร้างคู่มือ
- ข้ามงานค้นข้อมูลทั่วไป การแก้ปัญหาเฉพาะครั้ง หรือการคลิกเล็กน้อยประกอบงานที่ไม่มีขั้นตอนให้ใช้ซ้ำ หากผู้ใช้ขอคู่มือโดยตรง ให้ทำตามขอบเขตที่ขอ
- ตรวจคู่มือเดิมเฉพาะที่มีอยู่ในบริบทหรือที่เก็บที่ตกลงแล้ว หากยังตรงกับระบบให้ส่งลิงก์เดิม ปรับเฉพาะจุดที่เปลี่ยน ไม่ค้นทั้งเครื่องหรือสร้างฉบับซ้ำ
- หากผู้ใช้ไม่ต้องการคู่มือ ให้ทำเฉพาะงานหลัก

## เก็บระหว่างทำ

1. สรุปสั้น ๆ ว่าจะทำงานหลักพร้อมเก็บคู่มือ ใช้เครื่องมือและสกิล Browser/Computer ที่มีอยู่ตามข้อกำหนดของเครื่องมือนั้น
2. บันทึกจุดเริ่มต้น เมนู ชื่อปุ่ม ค่าที่เลือก เงื่อนไขหรือสิทธิ์ที่จำเป็น และผลที่สังเกตได้จากงานจริง แยกค่าตัวอย่างจากค่าที่ผู้ใช้ต้องเลือกเอง
3. แคปภาพเฉพาะหน้าจอสำคัญที่ช่วยหาปุ่มหรือเข้าใจผล ระหว่างอยู่หน้านั้น ใช้ภาพเดียวอธิบายหลายขั้นตอนที่ต่อเนื่องกันได้ ไม่แคปทุกคลิก
4. ใช้ภาพหน้าจอจริงเป็นหลัก รักษาบริบทพอให้เทียบกับแอปได้ และเพิ่มหมายเลข/ลูกศรโดยไม่บังปุ่มหรือค่าที่ต้องอ่าน
5. หลีกเลี่ยงภาพที่แสดงรหัสผ่าน OTP token ข้อมูลบุคคลหรือข้อมูลธุรกิจที่ไม่จำเป็น ปิดบังข้อมูลเหล่านั้นในภาพที่จะฝังหรือส่งมอบ เลือกข้อมูลตัวอย่างปลอดภัยเมื่อทำได้ภายในสิทธิ์เดิม
6. ภาพ Gen ใช้เฉพาะภาพประกอบที่ช่วยอธิบายและคุ้มกับงาน ติดป้ายว่าเป็นภาพประกอบ ไม่อ้างว่าเป็นภาพ UI จริงหรือใช้ยืนยันชื่อปุ่ม/สถานะ หากไม่มีภาพจริง ให้ระบุส่วนที่ยังยืนยันไม่ได้

การทำคู่มือไม่เพิ่มสิทธิ์ทำธุรกรรม ส่งข้อมูล เปลี่ยนระบบ หรือทดลองกับข้อมูลจริง หากต้องกลับเข้าแอป ทำรายการซ้ำ หรือทำขั้นตอนที่มีผลต่อข้อมูลเพื่อเก็บภาพเพิ่ม ให้แจ้งเหตุผลและขออนุญาตเฉพาะส่วนที่อยู่นอกงานเดิมก่อน ใช้หลักฐานที่เก็บไว้ทำส่วนที่เหลือได้ต่อ

## เขียนให้ทำตามได้

ใช้ภาษาไทย กระชับ และคงชื่อเมนู/ปุ่มตามหน้าจอจริง คู่มือควรมี:

- ชื่องาน เว็บไซต์/แอป และวันที่ตรวจขั้นตอน ระบุรุ่นเมื่อทราบ ไม่เดารุ่น
- จุดเริ่มต้นและสิ่งที่ต้องเตรียมเฉพาะที่จำเป็น ไม่ใส่ข้อมูลเข้าใช้งานลับ
- ขั้นตอนตามลำดับในรูป `หน้า → ปุ่ม → ค่า/สิ่งที่เลือก → ผลที่ควรเห็น` พร้อมภาพอ้างอิงและหมายเลขตรงกัน
- เกณฑ์รู้ว่าทำสำเร็จ และข้อควรระวังเฉพาะงาน เช่น บันทึกร่างต่างจากส่งจริงอย่างไร เมื่อยืนยันได้จากระบบ
- วิธีแก้ปัญหาสั้น ๆ เฉพาะที่พบหรือยืนยันได้ ไม่แต่งเมนู กรณีผิดพลาด หรือวิธีคืนค่าขึ้นเอง

ใช้ `<ค่าที่ต้องเลือกเอง>` แทนข้อมูลเฉพาะครั้ง และบอกวิธีเลือกเมื่อจำเป็น ทำให้ผู้ใช้เปลี่ยนเดือน ชื่อไฟล์ หรือรายการได้ ไม่ผูกคู่มือกับข้อมูลครั้งเดียว หากงานหยุดหรือไม่สำเร็จ ให้บอกขอบเขตที่ยืนยันแล้วและจุดที่ยังค้าง ไม่เรียกเป็นคู่มือที่ผ่านครบกระบวนการ

## รูปแบบและที่เก็บ

- ค่าเริ่มต้นคือส่ง HTML คู่กับ PDF เว้นแต่ผู้ใช้ระบุรูปแบบอื่น สร้าง PDF จากต้นฉบับ HTML เดียวกัน เพื่อให้ข้อความ ภาพ หมายเลขขั้นตอน และวันที่อ้างอิงตรงกัน ตั้งชื่อไฟล์ฐานเดียวกันในที่เก็บที่ตกลงแล้ว
- HTML เป็นไฟล์เดียว ฝังภาพที่ปิดบังข้อมูลแล้ว เปิดในเบราว์เซอร์ได้ ไม่ต้องติดตั้งและไม่ดึงภาพ/สคริปต์จากภายนอก ใช้หัวข้อและขนาดภาพที่อ่านชื่อปุ่มได้ รวมงานสั้นไว้หน้าเดียว
- PDF ใช้สำหรับเก็บ ส่งต่อ และพิมพ์ จัดรูปแบบพิมพ์จาก HTML ให้ภาพสัมพันธ์กับขั้นตอน ไม่ตัดข้อความหรือปุ่มสำคัญข้ามหน้า และไม่ย่อทั้งเอกสารจนอ่านไม่ออก ใช้ workflow ของสกิล `pdf` เมื่อมีให้ใช้
- ใช้ชื่อและตำแหน่งไฟล์ในพื้นที่ที่ผู้ใช้ตกลงสำหรับงานนั้น การอนุมัติที่เก็บสกิลนี้ไม่ใช่การอนุมัติที่เก็บคู่มือทุกงาน ห้ามเลือกสร้างโฟลเดอร์ถาวรหรือแชร์ขึ้น Cloud เอง
- หากยังไม่มีที่เก็บที่ตกลง ให้ถามเรื่องตำแหน่งขณะทำงานหลักต่อได้ เก็บหลักฐานชั่วคราวในพื้นที่งานเดิมตามสิทธิ์ที่มี ไม่ถือว่าความเงียบเป็นการอนุมัติ
- ไม่เพิ่มหน้าปก สารบัญ หรือจัดเล่มใหญ่เป็นค่าเริ่มต้น หากผู้ใช้ต้องการคู่มือจัดเล่มและสกิล `illustrated-web-manual` มีให้ใช้ ให้เรียกใช้ด้านการจัดหน้า โดยคงขอบเขตและหลักฐานของงานนี้ไว้
- ไม่ติดตั้ง dependency หรือบริการเพิ่มเพื่อทำคู่มือโดยไม่มีการอนุมัติ
- หากเครื่องมือที่มีสร้าง PDF ไม่ได้ ให้ส่ง HTML ที่ทำได้พร้อมระบุว่า PDF ยังไม่สำเร็จและสาเหตุ ไม่รายงานว่าส่งครบสองรูปแบบ และขออนุมัติก่อนเพิ่มเครื่องมือที่จำเป็น

## ตรวจและส่งมอบ

- ตรวจชื่อปุ่ม ลำดับ ค่า และผลกับหลักฐานที่เก็บไว้ แยกสิ่งที่ทำสำเร็จจริงจากสิ่งที่ยังไม่ได้ทดลอง
- เปิด HTML ที่ส่งมอบ ตรวจว่าภาพแสดงครบ อ่านไทยได้ หมายเลขสัมพันธ์กับขั้นตอน ไม่มีข้อมูลลับ และไม่มีข้อความ/ปุ่มสำคัญถูกบัง หากเปิดตรวจไม่ได้ให้รายงานตามจริง
- Render PDF เป็นภาพเพื่อตรวจทุกหน้า ตรวจข้อความไทย ภาพและหมายเลขว่าอ่านได้ ไม่ถูกตัดหรือทับกัน และเทียบกับ HTML ให้เนื้อหาครบตรงกัน หากแก้ต้นฉบับ ให้สร้าง PDF ใหม่และตรวจส่วนที่ได้รับผลกระทบก่อนส่ง หากยังตรวจไม่ได้ให้ระบุข้อจำกัดตามจริง
- ไม่เล่นซ้ำกระบวนการที่มีผลต่อข้อมูลเพียงเพื่อทดสอบคู่มือ ไม่อ้างว่าผู้ใช้ทดลองทำตามแล้วหากยังไม่ได้ทดลอง
- ส่งผลของงานหลักพร้อมลิงก์ HTML และ PDF แยกกัน ระบุผลตรวจและข้อจำกัดที่มีผลต่อการทำตาม เมื่อไม่มีข้อกังวลใหม่ไม่ตรวจวนซ้ำ

สกิลนี้เป็นแนวทางให้ AI พิจารณาเลือกใช้เมื่อแชตมองเห็นสกิล ไม่ใช่ระบบเฝ้าจอหรือการรับประกันว่าแชตอื่นได้โหลดแล้ว ไม่แก้ Instructions, สกิลอื่น หรือสร้าง automation เพิ่มเอง
